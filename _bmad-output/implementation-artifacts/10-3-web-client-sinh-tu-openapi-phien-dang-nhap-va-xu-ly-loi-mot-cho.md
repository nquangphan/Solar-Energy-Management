### 2. 🔥 BẪY SỐ 1 — `npm i openapi-typescript` ĐỎ ngay vì TypeScript 6

Đo thật 2026-10-22 trong scratch: `openapi-typescript@7.13.0` khai `peerDependencies: { typescript: "^5.x" }`, web đang ghim `typescript@6.0.3` ⇒ `npm install` báo **ERESOLVE**. Không có bản mới hơn (dist-tag `next` = `7.0.0-rc.1`, cũng `^5.x`).

**Cách đã đo là chạy được** — thêm vào `web/package.json`:

```json
"overrides": { "openapi-typescript": { "typescript": "$typescript" } }
```

Với override này: `npm install` sạch; sinh `openapi.json` hiện tại ra `schema.d.ts` 6591 dòng trong ~50ms; **sinh hai lần ra đúng byte**; `tsc --strict` (TS 6) typecheck một lời gọi `createClient<paths>().POST('/auth/login', …)` sạch.

**CẤM** dùng `--legacy-peer-deps` / `--force` (lockfile sẽ lệch máy khác) và **cấm** hạ TypeScript xuống 5.

### 3. 🔥 BẪY SỐ 2 — CLI và API lập trình KHÔNG ra cùng byte

Đo thật: CLI `npx openapi-typescript openapi.json -o x.d.ts` chèn header 4 dòng `/** This file was auto-generated by openapi-typescript… */`; API `openapiTS()` + `astToString()` thì không. Nếu script sinh dùng CLI mà drift-guard dùng API (hay ngược lại) ⇒ guard **luôn đỏ**, hoặc dev "sửa" bằng cách nới guard.

⇒ **MỘT hàm sinh duy nhất** (`buildApiSchema()`), script ghi file gọi nó, drift-guard gọi nó — đúng khuôn `design-system/permissions/build-permission-keys.mjs` (`buildOutputs()` dùng chung cho generator và `permission-keys.test.mjs`). Header "GENERATED … do not edit" do chính hàm đó chèn.

### 4. 🔥 BẪY SỐ 3 — 401 không phải lúc nào cũng là "token hết hạn"

Backend trả 401 `UNAUTHENTICATED` ở **ba nghĩa khác nhau**:

| Endpoint | 401 nghĩa là | Transport phải |
|---|---|---|
| `POST /auth/login` | sai email/mật khẩu | **KHÔNG refresh**; ném `ApiError` để Banner hiện "Thông tin đăng nhập không đúng" |
| `POST /auth/refresh` | refresh token sai/hết hạn/đã dùng | **KHÔNG refresh lại** (vòng lặp vô hạn); xoá phiên + báo hết phiên |
| `/auth/logout`, `/auth/forgot-password`, `/auth/reset-password` | (public) mã sai / email lạ… | **KHÔNG refresh**; ném `ApiError` |
| `POST /auth/change-password` | **mật khẩu hiện tại sai** ("Mật khẩu hiện tại không đúng") — `auth.service.ts:157-161` | refresh 1 lần → phát lại → vẫn 401 ⇒ **ném `ApiError` cho màn, KHÔNG đăng xuất** |
| mọi route khác | access token hết hạn / thiếu | refresh 1 lần → phát lại |

Luật đúng cho cả bảng: **(a)** không refresh cho 5 đường public `/auth/{login,refresh,logout,forgot-password,reset-password}`; **(b)** mỗi request chỉ phát lại **tối đa một lần**; phát lại vẫn 401 ⇒ ném `ApiError` (không refresh nữa, không xoá phiên); **(c)** chỉ khi **chính lời gọi refresh** hỏng mới xoá phiên + `onSessionExpired`.

**D2 — Client sinh:** `openapi-typescript@7.13.0` (devDep, chỉ sinh type) + `openapi-fetch@0.17.0` (dep runtime, ~6 kB, một dep con `openapi-typescript-helpers`). Ghim **chính xác** version (không `^`), đúng thói quen `web/package.json`. Script `"api:gen": "node scripts/generate-api.mjs"`.
- `buildApiSchema()` đọc `../backend/openapi/openapi.json` (đường dẫn tính từ `import.meta.url`, không từ `cwd`), gọi `openapiTS(spec)` + `astToString(ast)`, chèn header `// GENERATED from backend/openapi/openapi.json — do not edit by hand; regen: \`cd web && npm run api:gen\`.` + `/* eslint-disable */` (giống `permission-keys.generated.ts`). **D3 — Transport = hàm `fetch` tuỳ biến truyền cho `openapi-fetch`.** Đo thật: `openapi-fetch@0.17` gọi `fetch(request: Request, init)` với **một `Request` đã dựng sẵn**, và lỗi do `fetch` tuỳ biến **ném ra được truyền nguyên vẹn** tới caller (`instanceof` giữ được). Vì vậy:
- `createTransport({ baseUrl, session, fetchImpl = globalThis.fetch.bind(globalThis), onSessionExpired })` trả `{ fetch(request): Promise<Response> }`.
- Gắn `Authorization: Bearer <access>` (trừ 5 đường public, mục 4).
- **Clone trước khi gửi**: `const retry = request.clone()` TRƯỚC lần gửi đầu — body là stream, gửi xong không đọc lại được (multipart 10.5 cũng đi đường này).
- `!response.ok` ⇒ parse envelope **ở đây** rồi **ném `ApiError`** ⇒ nhánh `{ error }` của openapi-fetch không bao giờ chạy; adapter dùng `data` trực tiếp. Đây là "đúng một chỗ" của AC-3.
- `fetchImpl` ném (mất mạng, CORS chặn, DNS) ⇒ ném `ApiError` không `status`/`code`, message mạng (D5).
- `AbortError` (caller huỷ) ⇒ ném lại nguyên vẹn, không bọc.

**D4 — `ApiError`** (`web/src/api/api-error.ts`):

```ts
export class ApiError extends Error {
  readonly status?: number;     // vắng khi request không tới được backend
  readonly code?: string;       // envelope.code (AD-5) — màn rẽ nhánh theo cái này
  readonly fieldErrors?: { field: string; code: string; message: string }[];
  readonly traceId?: string;
}
```

Cấu trúc này là **siêu tập** của mọi `*PortError` hiện có (`message` + `code?` + `status?` + `fieldErrors?` với `{field, message}`) ⇒ màn đang đọc `.message`/`.code`/`.fieldErrors`/`.status` dùng được ngay, **không sửa màn nào**. Không sửa các interface `*PortError` ở story này (10.4/10.5 viết lại port theo type sinh).
- Type của envelope lấy từ type sinh: `components['schemas']['ErrorEnvelopeDto']` — **không khai tay** (AD-12).
- Kiểm envelope tối thiểu: object, `typeof code === 'string'`, `typeof message === 'string'`; `fieldErrors` chỉ nhận khi là mảng, bỏ phần tử sai hình. Không đạt ⇒ "body không phải envelope".

**D5 — Thông điệp do client tự viết (chỉ khi backend không nói gì):**
- Body không phải envelope (HTML 502 của proxy, rỗng, JSON lạ): `'Không thực hiện được. Thử lại.'` — đúng chuỗi fallback đang có ở `CustomerPickScreen.tsx:349`. `status` = HTTP status thật, `code` vắng.
- Không tới được máy chủ: `'Không kết nối được máy chủ. Kiểm tra mạng rồi thử lại.'` — `status`/`code` vắng.
- Hết phiên (refresh hỏng): dùng nguyên `message` của envelope 401 refresh nếu có, không thì `'Phiên đăng nhập đã hết hạn. Đăng nhập lại.'`.
Envelope hợp lệ ⇒ `message` hiển thị **nguyên văn** (luật có sẵn ở comment `CustomerPortError`).

**D6 — Refresh single-flight trong transport:**
- Một biến `refreshing: Promise<boolean> | null` trong closure transport. 401 trên route không public ⇒ nếu `refreshing` đang chạy thì `await` chung; nếu không thì tạo mới, `finally` đặt lại `null`.
- Request gửi bằng access token **cũ** mà nhận 401 sau khi request khác đã refresh xong (token hiện tại ≠ token đã gửi) ⇒ **phát lại luôn**, không refresh lần nữa.
- Refresh gọi **`fetchImpl` trực tiếp** `POST {baseUrl}/auth/refresh` (không đi qua openapi-fetch để không đệ quy vào chính transport), body `{ refreshToken }` đọc từ `session-store` **ngay lúc gọi** (tab khác có thể vừa rotate). Type body/response lấy từ `components['schemas']['RefreshRequestDto' | 'AuthTokensDto']`.
- Refresh OK ⇒ lưu cả access mới lẫn refresh mới (backend rotate — giữ refresh cũ ⇒ lần sau 401 chắc chắn).
- Refresh hỏng (401, envelope khác, non-envelope, mạng) ⇒ `session.clear()` + `onSessionExpired()` **đúng một lần** cho cả loạt request đang chờ; mọi request chờ bị ném `ApiError` (status 401, code `UNAUTHENTICATED`).
- Không có refresh token mà nhận 401 ⇒ coi như refresh hỏng (không gọi mạng).
- KHÔNG làm refresh chủ động theo `expiresIn` (YAGNI — 401 là đủ).

**D7 — Lưu token (mặc định §6.13):** `session-store.ts`: access token biến trong bộ nhớ; refresh token `localStorage` key `pns.refreshToken`. Mọi truy cập `localStorage` bọc `try/catch` (Safari private / bị chặn ⇒ coi như không có token, không crash). API: `getAccessToken()`, `getRefreshToken()`, `setTokens({accessToken, refreshToken})`, `clear()`. Không lưu `expiresIn`.

**D8 — Port đăng nhập** (`design-system/session/auth-port.ts`, tên tiếng Anh):

```ts
export interface AuthPort {
  /** POST /auth/login — rejects with the AD-5 error (401 wrong credentials, 400 validation). */
  login(input: { email: string; password: string }): Promise<void>;
  /** Start-up: trade the stored refresh token for an access token. false ⇒ show Đăng nhập. */
  restoreSession(): Promise<boolean>;
  /** POST /auth/logout with the stored refresh token; ALWAYS clears the local session. */
  logout(): Promise<void>;
}
```

- Token **không** đi ra khỏi port (màn không bao giờ cầm token). `login` thành công ⇒ `session.setTokens(...)`.
- `restoreSession()` = refresh dùng chung single-flight của transport (transport lộ thêm `refreshSession(): Promise<boolean>`), không viết logic refresh lần hai. Đây là cách AC "refresh" của port được cài; transport vẫn là nơi duy nhất làm refresh (spine AD-12).
- `logout`: gọi `POST /auth/logout` (có refresh token thì gửi; không thì bỏ qua lời gọi), **xoá phiên trong `finally`** — mạng hỏng vẫn đăng xuất cục bộ; lỗi logout bị nuốt (backend idempotent, phiên tự hết hạn).
- `FakeAuthPort` (TEST/DEMO-ONLY): `rejectWith?: Error` cho `login`, `restored = false`; header comment theo khuôn `fake-password-port.ts`. Export cả hai qua `design-system/session/index.ts`.
