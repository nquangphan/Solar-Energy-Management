- (decision) Repo: TÁCH RIÊNG 3 repo — backend API, web FE (React), mobile (Flutter). Không monorepo. Ranh giới = hợp đồng REST API; kèm OpenAPI spec để web sinh client có type, chống lệch contract
- (direction) ĐÍNH CHÍNH entry trước: KHÔNG bàn chuyện tách repo. Ý là tách TẦNG LOGIC
- (decision) INVARIANT ranh giới: Web (React) và Mobile (Flutter) là CLIENT thuần, chỉ giao tiếp qua REST API; KHÔNG client nào truy cập DB trực tiếp. Backend (Node) là chủ sở hữu DUY NHẤT của DB & mọi truy cập dữ liệu/nghiệp vụ. Prevents: FE query thẳng DB, logic nghiệp vụ rò xuống client, hai nguồn sự thật
- (decision) Hệ quả: mọi quy tắc nghiệp vụ (tính giá/VAT, snapshot, chuyển trạng thái, phân quyền, tồn kho) thực thi Ở BACKEND; client chỉ hiển thị + gọi API. Cấu trúc repo (mono/đa) để MỞ, không phải invariant
- (decision) Lưu file/ảnh đính kèm: OBJECT STORAGE Cloudflare R2 (S3-compatible), TÁCH khỏi VPS (không lưu đĩa VPS). Backend quản lý upload + truy cập qua signed URL/proxy; DB chỉ lưu metadata + key object. (ghi đè khuyến nghị #6 đĩa VPS)
- (decision) UI gating theo QUYỀN của account đang đăng nhập: full quyền → thấy toàn bộ UI; thiếu quyền nào → ẨN hoặc DISABLE control tương ứng. Client render theo effective permission set
- (decision) Backend trả EFFECTIVE PERMISSION SET của account qua API (khi login / endpoint /me) để client biết đường ẩn/disable. NHƯNG backend VẪN enforce mọi quyền server-side ở mỗi request — ẩn/disable ở client chỉ là UX, KHÔNG phải lớp bảo mật (không tin client)
- (decision) Error handling: MỌI API trả lỗi theo CHUNG 1 cấu trúc (error envelope: code, message, details?, fieldErrors?, traceId) + HTTP status chuẩn. Backend có lớp xử lý lỗi TẬP TRUNG (exception filter/middleware) map mọi lỗi về envelope. FE (web+mobile) handle lỗi Ở 1 CHỖ COMMON (API interceptor) → toast/thông báo nhất quán. Prevents: mỗi endpoint mỗi kiểu lỗi, FE rải rác try/catch
- (decision) DESIGN-SYSTEM-FIRST: dựng tầng design system từ DESIGN.md TRƯỚC mọi màn tính năng, cho CẢ web lẫn mobile. Triển khai theo từng nền tảng: thư viện component React (web) + thư viện widget Flutter (mobile), cả hai TUÂN cùng 1 hợp đồng thị giác DESIGN.md (token màu Năng Lượng Sạch, style Viền nét, 9 chip trạng thái, bộ icon SVG, topbar/botnav/frame). MỌI màn sau này BẮT BUỘC dùng component/token của design system — cấm style ad-hoc. Prevents: mỗi màn style riêng, web-mobile lệch nhau, drift khỏi DESIGN.md
